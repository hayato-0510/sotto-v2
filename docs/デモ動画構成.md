# デモ動画構成

応募用のデモ動画（約1分）の構成と撮り方。2026年9月10日に決めた。

| 項目 | 内容 |
| :--- | :--- |
| 長さ | 約60秒 |
| 一番伝えること | **声をかけずに席を渡せる体験** |
| 撮り方 | 2台の画面録画だけ。人は映さず、状況はナレーションで補う |
| 画面の並べ方 | 左に受け手（席をさがす）、右に譲る側（席を空ける）。同じ時間軸で同時に流す |

人を映す案（室内で座席を再現する、実際の電車で撮る）は、時間が足りないため見送った。人の動きは、譲る側の画面に出る動作の文（生成AIが作る「立ち上がり通路側へ寄り、経路を作る」等）が語る。

---

## 1. 構成

| 時間 | 左：受け手（席をさがす） | 右：譲る側（席を空ける） | ナレーション（案） |
| :--- | :--- | :--- | :--- |
| 0:00–0:08 | （静止） | （静止） | 席を譲りたい。でも、声をかけられない。相手が本当に必要としているのか、分からないから。 |
| 0:08–0:16 | 「こう受け取りました」＋要約 →［ これで発信する ］→「席がほしい、と発信しています」 | （静止） | 席が必要な人は、乗ったらボタンを一つ押しておく。 |
| 0:16–0:26 | 発信中のまま | 「いまは近くにいません」→「すぐ近くに、席を必要としている人がいます」 | 座っている人の画面には、すぐ近くに席を必要としている人がいる、とだけ出る。相手がどんな事情かは出ない。 |
| 0:26–0:38 | **同じ瞬間に**「ごく近くの人が席を空けます」 | 混み具合を選ぶ →［ 譲る ］→ 動作（例「立ち上がり通路側へ寄り、経路を作る」） | 混み具合を選んで、譲るを押す。生成AIが、その場に合った動き方を返す。同じ瞬間、相手の画面にも届く。 |
| 0:38–0:48 | ［ ありがとう ］→「伝えました」 | 「そっと伝わりました」 | 座れたら、ありがとうを一つ。 |
| 0:48–1:00 | タイトル「Sotto」とコンセプトの一文 | | 声をかけず、相手を判断することもなく、席が渡る。 |

ナレーションは1秒に6〜7文字で読んで各区間に収まる長さにしてある。

---

## 2. 撮影の前に満たすこと

**2台での受け渡しが実際に動くこと。** この構成の中心（右で［ 譲る ］を押すと左が変わる）は、近接検知と2台の間の受け渡し（GATT）が実機で動くことを前提にしている。2026-09-10 に S10 と A51 で成立を確認した（[`spike-results.md`](spike-results.md)）。別の端末で撮るときは §1〜§3 を回し直す。

**0:08 の区間の受け手の画面は「こう受け取りました」＋要約。** 収録の直前に受け手で4択→［ つづける ］まで進め、この画面で止めてから録画を始める（発信はまだ押さない）。

---

## 3. 編集で守ること

**「押した瞬間に右が変わる」場面は切らない。** 左で［ 譲る ］を押してから右の画面が変わるまでを、撮れたままの速さで見せる。ここを編集で合わせると、まだ測っていない「0.5秒以内に届く」（NFR-02）を映像で作ることになる。

片方の画面の中の待ち時間（AI が要約や動作を作る数秒）は詰めてよい。時間の見え方が変わるだけで、起きたことは変わらないからである。

---

## 4. 収録の手順（2026-09-10 に実施・確定）

**scrcpy の画面ストリーミングは使わない。** 無線 adb と同じ Wi-Fi を食い合い、
2台間の BLE GATT 接続が受け渡しの途中で切れた（実際に撮り直しになった）。
**端末内で録画する `adb screenrecord` を使う。** 通信を増やさないので GATT が安定する。

1. 2台を無線 adb で繋ぐ（USB は距離を測るとき邪魔になる）
2. 収録前に環境ノイズを消す（[`spike-results.md`](spike-results.md) の「気づき」）
   - 周囲のスマートウォッチ等の BLE 機器とコンパニオンアプリを止める
   - 譲る側の端末をスリープさせない設定にする
   - 他アプリの前面割り込みを止める
   - BLE 権限を先に付与しておくと権限ダイアログが挟まらない
3. 受け手を「こう受け取りました」＋要約の画面に、譲る側を「いまは近くにいません」にする
4. 両端末で同時に録画開始：
   ```bash
   adb -s <受け手> shell screenrecord --time-limit=80 --bit-rate 8000000 /sdcard/rec.mp4 &
   adb -s <譲る側> shell screenrecord --time-limit=80 --bit-rate 8000000 /sdcard/rec.mp4 &
   ```
5. §1 の順に操作する。同時に開始したので2本は自然に揃う
6. `adb shell pkill -SIGINT screenrecord` で止め、`adb pull` で回収
7. ffmpeg で左右に並べる：
   ```bash
   ffmpeg -ss 6 -t 56 -i 受け手.mp4 -ss 6 -t 56 -i 譲る側.mp4      -filter_complex "[0:v]scale=-2:1000,setsar=1,pad=iw+6:ih:0:0:color=0xDDDDDD[l];     [1:v]scale=-2:1000,setsar=1[r];[l][r]hstack=inputs=2,format=yuv420p[v]"      -map "[v]" -r 30 -c:v libx264 -crf 23 demo/sotto-2画面-素材.mp4
   ```
8. ナレーションとタイトルは編集で足す

**撮れた素材** は `demo/` にある。`sotto-2画面-素材.mp4`（左右合成・約60秒）と、
各端末の元動画 `席をさがす側-素材.mp4` `席を空ける側-素材.mp4`。
この回の受け手の需要は「立っているのがつらい」、混み具合は「混んでいる」を選んだ。
