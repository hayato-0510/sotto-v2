# デモ動画構成

応募用のデモ動画（約1分）の構成と撮り方。2026年9月10日に決めた。

| 項目 | 内容 |
| :--- | :--- |
| 長さ | 約60秒 |
| 一番伝えること | **声をかけずに席を渡せる体験** |
| 撮り方 | 2台の画面録画だけ。人は映さず、状況はナレーションで補う |
| 画面の並べ方 | 左に譲る側、右に受け手。同じ時間軸で同時に流す |

人を映す案（室内で座席を再現する、実際の電車で撮る）は、時間が足りないため見送った。人の動きは、譲る側の画面に出る動作の文（生成AIが作る「立って、座面に手を添えたまま…」）が語る。

---

## 1. 構成

| 時間 | 左：譲る側 | 右：受け手 | ナレーション（案） |
| :--- | :--- | :--- | :--- |
| 0:00–0:08 | （暗いまま） | （暗いまま） | 席を譲りたい。でも、声をかけられない。相手が本当に必要としているのか、分からないから。 |
| 0:08–0:16 | （暗いまま） | 「こう受け取っています」→［ これで発信する ］→「席がほしい、と発信しています」 | 席が必要な人は、乗ったらボタンを一つ押しておく。 |
| 0:16–0:26 | 「いまは近くにいません」→「すぐ近くに、席を必要としている人がいます」 | 発信中のまま | 座っている人の画面には、すぐ近くに席を必要としている人がいる、とだけ出る。相手がどんな事情かは出ない。 |
| 0:26–0:38 | 混み具合を選ぶ →［ 譲る ］→ 動作「立って、…」 | **同じ瞬間に**「ごく近くの人が席を空けます」 | 混み具合を選んで、譲るを押す。生成AIが、その場に合った動き方を返す。同じ瞬間、相手の画面にも届く。 |
| 0:38–0:48 | 「そっと伝わりました」 | ［ ありがとう ］→「伝えました」 | 座れたら、ありがとうを一つ。 |
| 0:48–1:00 | タイトル「Sotto」とコンセプトの一文 | | 声をかけず、相手を判断することもなく、席が渡る。 |

ナレーションは1秒に6〜7文字で読んで各区間に収まる長さにしてある。

---

## 2. 撮影の前に満たすこと

**2台での受け渡しが実際に動くこと。** この構成の中心（左で［ 譲る ］を押すと右が変わる）は、近接検知と2台の間の受け渡し（GATT）が実機で動くことを前提にしている。どちらもまだ実機で確かめていない。撮影の前に [`手動確認.md`](手動確認.md) の §1〜3 を2台で回し、結果を `docs/spike-results.md` に残す。落ちたら構成から見直す。

**受け手の需要を先に保存しておく。** 0:08 の区間は、保存した需要から1タップで発信する画面（設計書 §3.4）を撮る。撮影の前に受け手の端末で一度4択から発信し、要約を保存しておく。

---

## 3. 編集で守ること

**「押した瞬間に右が変わる」場面は切らない。** 左で［ 譲る ］を押してから右の画面が変わるまでを、撮れたままの速さで見せる。ここを編集で合わせると、まだ測っていない「0.5秒以内に届く」（NFR-02）を映像で作ることになる。

片方の画面の中の待ち時間（AI が要約や動作を作る数秒）は詰めてよい。時間の見え方が変わるだけで、起きたことは変わらないからである。

---

## 4. 収録の手順

2台を別々に録画すると開始時刻がずれ、並べるときに編集で揃えることになる。それでは §3 を守れないので、**2台の画面を PC に並べて映し、その範囲を1本の録画で撮る。**

1. scrcpy を入れる（`winget install Genymobile.scrcpy`）
2. 2台を USB で繋ぎ、`adb devices` で両方の識別子を確かめる
3. 1台ずつ画面を PC に映す。左に譲る側、右に受け手を置く

   ```bash
   scrcpy -s <譲る側の識別子> --window-title 譲る側 --no-audio
   scrcpy -s <受け手の識別子> --window-title 受け手 --no-audio
   ```

4. Windows 11 の Snipping Tool の録画で、2つの画面を含む範囲を撮る
5. ナレーションとタイトルは編集で足す
