# 手動確認チェックリスト（Android 実機2台）

設計書 §8.3 のとおり、実機2台での通し確認は自動化しない。このリストで行う。
**このビルドは実機での近接検知を一度も検証していない**（開発計画 §1）。ここでの結果が事実上のスパイクになる。
結果は通っても落ちても `docs/spike-results.md` に残す。

| 項目 | 内容 |
| :--- | :--- |
| 用意するもの | Android 12 以上の実機2台（Bluetooth オン・ネット接続あり）、APK、メジャー（距離を測る） |
| 所要時間 | 20〜30分 |
| 記録するもの | 各項目の ○／✕、気づいたことは一言でよい。数値は分かる範囲で |

---

## 0. インストール

- [ ] 2台とも APK をインストールできた（「提供元不明のアプリ」の許可が要る）
- [ ] 起動して「席がほしい」「いま座っている」の2択が出る
- [ ] 最下部に「いまは Android どうしでのみつながります」と、実機未検証の注記が出ている

## 1. 受け手（端末A）：需要の宣言

- [ ] ［ 席がほしい ］→ 4択のどれかを押す（＋自由記述は任意）→［ つづける ］
- [ ] 数秒で「こう受け取りました」と要約が出る（**出た文が体験の記述として自然か**を見る）
  - 「定型の内容になっています」と出た場合：AI サーバに繋がっていない。`/api/health` を確認
- [ ] ［ これで発信する ］→ Bluetooth と通知の権限を聞かれる → 許可
- [ ] 「席がほしい、と発信しています」に変わる
- [ ] 通知欄に「席がほしい、と発信中」が常駐している（発信中の明示。設計書 §1.4）
- [ ] 画面を消してポケットに入れる

## 2. 譲る側（端末B）：需要の提示

- [ ] ［ いま座っている ］→ 権限を許可
- [ ] 端末A が **1m 以内**にあると「すぐ近くに、席を必要としている人がいます」が出る（**何秒で出たか**）
- [ ] 端末A を **5m 以上**離すと「いまは近くにいません」に戻る（**戻るまで何秒か**）
  - 戻らない／近くでも出ない場合：RSSI 閾値（`mobile/lib/ble.dart` の `nearRssiDbm` と Kotlin 側 `Gatt.NEAR_RSSI_DBM`、暫定 -75）を疑う。**どの距離でどう見えたかを記録する**
- [ ] 端末A をポケットに入れた状態でも 1m で出る
- [ ] 端末A の画面を消したまま **5分**待っても、端末B で出続ける（背景での発信）

## 3. 受け渡し

- [ ] 端末B で混み具合を1つ選び［ 譲る ］
- [ ] 端末B に動作（「立って、…」）と「およそ◯秒 ／ 理由」が出る（**押してから何秒か**）
  - 「定型の案内を表示しています」と出た場合：AI 生成に失敗している。数回試して頻度を記録
  - 動作の文に「声をかける」「すみません」などの**発話が一切含まれていない**ことを確認（FR-12）
- [ ] **ほぼ同時に**端末A の画面が「ごく近くの人が席を空けます」に変わる（**端末B の表示から何秒後か**。目標 0.5 秒）
- [ ] 端末A で［ ありがとう ］→ 端末B に「そっと伝わりました」が出て、数秒で元に戻る
- [ ] 端末A は「伝えました」→［ 閉じる ］で最初に戻り、常駐通知が消える

## 4. 取り消しと失敗の経路

- [ ] もう一度 1〜3 を進め、端末B の動作画面で［ やめる ］→ 端末A に「まだ探していますね」が出て、発信中に戻る
- [ ] もう一度進め、端末A で「見つからない」→ 端末B に「相手が見つけられないようです」、端末A に「近くで見つかりませんでした」と［ 待つ ］
- [ ] 端末A で［ 待つ ］→ 発信中に戻り、端末B で再び「すぐ近くに…」が出る
- [ ] 端末B の動作画面で、端末A のアプリを強制終了 → 端末B が数秒で「いまは近くにいません」に戻る

## 5. 混み具合で動作が変わるか（AI-2、設計書 §2.1）

- [ ] 同じ端末A の需要に対し、端末B で「空いている」「ぎゅうぎゅう」を選んで2回譲る。**動作の文が変わるか**
- [ ] 最初の画面の「審査用：混み具合で動作がどう変わるか」で3列が並ぶ

## 6. 心理的抵抗（設計書 §9-2）

- [ ] 「ぎゅうぎゅう」で出た動作（座面に手を添えて待つ、等）を、**実際の電車でやれると思うか**。一言で

## 落ちたときの見方

| 症状 | 疑う場所 |
| :--- | :--- |
| 「サーバに接続できません」 | `mobile/lib/api.dart` の `apiBase`（ビルド時の `--dart-define=SOTTO_API_BASE`）と、Vercel 側の稼働 |
| 「定型の内容／案内」ばかり | Vercel の環境変数 `GOOGLE_API_KEY`。`/api/health` の `provider` が `google` か |
| 近くにいても出ない | 端末B の Bluetooth と権限。端末A の通知欄に常駐があるか。RSSI 閾値 |
| 遠くでも出る | RSSI 閾値が緩い。送信出力（`DemandPeripheral.kt` の `ADVERTISE_TX_POWER_MEDIUM`）を LOW に |
| ［ 譲る ］で「相手の端末に接続できませんでした」 | GATT 接続（スパイク3相当）が落ちている。端末の機種名と Android バージョンを記録 |
| 端末A の画面が変わらない | 通知（OUTBOX）か書き込み（INBOX）が届いていない。同上 |
