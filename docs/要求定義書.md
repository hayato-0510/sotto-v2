# Sotto v2 要求定義書

> **席を譲りたい人が、声をかけられないまま、必要な人に席を渡せる。**

譲る意思を持つ人は約8割いるのに、妊婦や体調不良者が実際に座れる機会は「片手で数えるほど」しかない。この差を埋めていないのは冷たさではない。譲りたい側が、声をかける直前で固まるからだ。Sotto はその固まりを直そうとせず、**固まったままで席が動く**仕組みを作る。

## 0. コンセプト（すべての判断の基準）

> **席を譲りたい人が、声をかけられないまま、必要な人に席を渡せる。**

この1文には3つの要求が畳み込まれている。主役は席を譲りたい人であること。消すのは声かけであって、固まりそのものは直さないこと。そしてゴールは、席が必要な人に実際に渡ることである。

以降のすべての要求・要件・設計判断は、この1文に資するかで評価する。資さない議論や機能はスコープ外とする。

なお主役とゴールは意図的にずらしてある。**主役は譲る側だが、成功指標は「席を必要とする人が座れた」に置く。** 譲る側が気持ちよくなるだけで誰も座れない状態は、この1文を満たしていない。

---

## 1. 背景：譲る意思は足りている。足りないのは最後の一歩

数字が示す矛盾は単純だ。譲る意思を持つ人は約8割存在する（各社アンケート調査）。それでも妊娠7ヶ月の当事者が実際に座れた割合は「片手で数えるほど」に留まる（弁護士JP調査）。意思は足りている。足りていないのは、意思を行動に変える最後の一歩である。

その一歩を止めているものが何かは、すでに調査で分かっている。譲らない理由の1位は「相手に失礼になるかもしれない」46.4%（内閣府調査）。さらに「以前に断られた経験がある」が20.4%（エアトリ調査）を占める。どちらも**誤爆と拒絶への恐怖**である。妊婦でなかったら失礼になる、要らないと言われたら気まずい、と考えているうちに電車は次の駅に着く。

受け手の側も同じ理由で動けない。つわり・貧血・内部障害・パニック障害は外見から100%健康に見えるため、「席を譲ってください」と言うこと自体が極めて高いハードルになる。恐怖の形は同じで、向きが逆なだけである。

ヘルプマークや声かけ・サポート運動（&HAND / May ii を含む）は、9年間ずっと譲る側に「勇気を出して声をかけよう」と呼びかけてきた。呼びかけは恐怖を消さない。46.4%の人が抱えているのは勇気の不足ではなく、判断を誤るリスクだからだ。

**ここから導かれる結論**：解決すべきは声のかけやすさではなく、**声をかける工程そのものをなくすこと**である。そしてもう一つ、**判断を誤る可能性を構造から消すこと**。後者は v3.0 では言語化されていなかった要求であり、今回の作り直しで最も大きく変わった点にあたる。

---

## 2. 主役は、譲りたいのに動けなかった人

**田中（22歳・学生）** — 座席に着席中。目の前に立っている人が体調が悪そうに見える。譲る気はある。しかし妊婦でなかったら失礼だし、断られたら気まずい、と考えているうちに動けなくなる。発案者自身の実感がこのペルソナの出所である。

**佐藤（28歳・妊娠初期）** — 外見からは100%健康に見える。めまいと吐き気で立っているのが限界だが、声を出して頼む勇気はない。

主役を田中に置いたのは折衷ではない。佐藤の問題（頼めない）には9年分の施策が積み上がっている一方、田中の問題（やりたいのにできない）にはほとんど手が入っていない。手薄なほうを狙う。

佐藤の状態（つわり・貧血・怪我・内部疾患）は、コンセプト文には出さない。これらは §4 の AI-1 が読み解く入力の例であって、プロダクトの見出しではない。

## 3. コアミッション

> 声をかけられるようにするのではなく、声をかけずに済ませる。
> 加えて、**譲る側が「相手は本当に席を必要としているのか」を判断せずに済む状態**を作る。

前半は v3.0 から引き継いだ。後半が今回の追加である。46.4%の恐怖の中身が「判断を誤ること」だと分かった以上、無言化だけでは足りない。明示的に「席がほしい」と言った人にしか繋がらない構造にすれば、譲る側は判断を間違えようがなくなる。

## 4. なぜ生成AIでなければならないか

固定ルール（if文）で足りるなら、AIを使う理由はない。ここが弱いと審査で最も痛い指摘を受けるため、責務を3つに分けて必然性を示す。

| # | 責務 | 固定ルールでは何ができないか | AIが果たす役割 |
| :---: | :--- | :--- | :--- |
| AI-1 | 自由記述から個別制約を読み解く | 「貧血気味で立っていられない」「ギプスで座ると逆に痛い」など、個人の困りごとは無限にあり選択肢で網羅できない | 自由なテキストから「座位が必要か」「支えが要るか」「避けたいこと」を機械可読な構造データ（Needs）へ正規化する |
| AI-2 | 混雑度に応じた身体動作を即興で生成する | 空いている時と超満員では正解の動作が真逆になる。空いていれば立ってすぐ離れてよいが、混雑時に離れると横取りされる | その場の混雑度と身体制約から「立って一歩ずれる」「座面に手を添えて待つ」などの動作を組み立てる |
| AI-3 | 角を立てない語気に調律する | 「席を譲ってください」という命令形は義務感を生み、断る自由を奪う | 「〜していただけると助かります」のような、善意を搾取しない語気を生成する |

このうち AI-2 の重みが v3.0 より増している。混雑度によって挙動を切り替える判断は、設計上もプロダクトの性格を決めるダイヤルとして機能するようになった（[`設計書.md`](設計書.md)参照）。AI-1 と AI-3 は前身から実運用でチューニング済みで、こちらは変更していない。

いずれも §0 のコンセプトを成立させるための責務であり、AI自体が目的ではない。追加してよいのは、AI-1 から AI-3 のいずれかに寄与する機能だけである。

### 4.1 AIがやってはいけないこと

医療・健康上の診断や体調の推定を行ってはならない。

出力に「声」「話す」「言う」「すみません」などの発話指示を一切含めてはならない。§0 の「声をかけられないまま」を直接支える制約であり、最優先で守る。プロンプトでの禁止に加えてサーバ側で検証する（[`AGENTS.md`](../AGENTS.md) §2）。

「走って移動する」「人混みを無理にかき分ける」などの危険動作を出力してはならない。

## 5. 望ましい体験

朝の混雑した通勤電車を想定する。カメラは田中の一人称で回る。

1. 田中は座っている。目の前に立っている佐藤が、少し辛そうに見える。声をかけようとして、いつも通り固まる。
2. 田中がスマホを開く。自分の意思で開く場面と、通知リストに静かに積まれていた「近くに、席を必要としている人がいます」に気づいて開く場面のどちらもありうる。音も振動も鳴らない。
3. 画面には「すぐ近くに席を必要としている人がいます」とだけ出ている。**ここに表示されるのは、自分から「席がほしい」と発信した人だけである。** 田中は相手が妊婦かどうかを判断しなくてよい。誤爆がありえない。
4. 田中が今の混み具合を1タップで選び、［ 譲る ］を押す。
5. 田中の画面に動作が出る。混雑時なら「立って、座面に手を添えたまま。相手が座るまでそこで待ってください」。空いていれば「立って、ポール側へ。そのまま離れて大丈夫です」。どちらにも声をかける指示は含まれない。
6. 佐藤の画面が反応する。「ごく近くの人が席を空けます」。
7. 田中が立ち、視線を外して半歩ずれる。佐藤が1〜2歩で座る。
8. 佐藤が［ ありがとう ］を押す。田中の画面に「そっと伝わりました」と出て、田中は離れてよいと分かる。

二人は一度も会話せず、目線も合わせない。そして田中は、一度も相手の状態を判断していない。

**譲らない選択も体験の一部である。** 田中が3の画面を見て、そのままアプリを閉じてもよい。何も起こらず、佐藤は田中が見たことすら知らない。理由を聞かれることも、断ったと記録されることもない。この「不可視のノー」は機能を追加せずに成立している。
